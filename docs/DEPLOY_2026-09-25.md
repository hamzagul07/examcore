# Deploy runbook — code review 2026-09-25 fixes

Companion to `docs/CODE_REVIEW_2026-09-25.md`. Everything below is what the
fixes need from the *environment*; the code degrades gracefully when a step
is late, but each gap is listed so nobody is surprised by the fallback.

## 1. Migrations (`supabase/migrations/20260925_*.sql`)

All are idempotent. Apply **before or with** the deploy, in this order:

| # | Migration | Why the order matters |
|---|-----------|-----------------------|
| 1 | `20260925_user_subscriptions_polar_modified_at.sql` | The webhook ordering guard needs the stored version column; until then only the "superseded" case (dead event vs another live subscription) is caught, not a stale event for the same subscription. |
| 2 | `20260925_mark_runs_reservation_event_id.sql` | The sweep can only release leaked reservations once `mark_runs.reservation_event_id` exists; the routes skip the column (one warning) until then. |
| 3 | `20260925_reserve_mark_usage_credits.sql` | Credits are only held under the advisory lock once this lands; before it the TS falls back to the legacy RPC (credit consumed at finalize — the original race). |
| 4 | `20260925_credit_refund_cumulative.sql` | Partial refunds keyed on the cumulative amount. |
| 5 | `20260925_rate_limit_rpc.sql` | Atomic guest slots. Until applied `lib/rate-limit.ts` logs one warning and uses the old non-atomic read→upsert (nothing breaks; the race is not closed). |
| 6 | `20260925_mark_runs_client_scope.sql` | Per-caller idempotency keys. Either order: without it `/api/mark/process` logs `idempotency lookup failed` once per keyed request and proceeds without dedupe. |
| 7 | `20260925_whole_paper_question_patch.sql` | Per-question retry RPCs (`patch_whole_paper_question`, `set_whole_paper_aggregate`). |
| 8 | `20260925_community_reports_and_notifications.sql` | **Must land before the deploy**: `lib/community/notify.ts` writes `notifications.actor_id` on every insert, so in-app notifications fail until it exists. |
| 9 | `20260925_community_votes_rpc.sql` | `vote_post` / `vote_comment`; also carries the current copy of `audit_client_grants` (adds `classroom_join_attempts` to the service-only list). |
| 10 | `20260925_community_uploads_policy.sql` | Scopes `community-uploads` reads to the uploader's folder. The mobile app must stop signing other users' paths itself (see §4). |
| 11 | `20260925_classroom_join_attempts.sql` | Invite-code guard table. Until applied the guard fails open with a one-time warning (codes `42P01`/`PGRST205` only); any other DB error is a 503. |

Then run `pnpm test:grants` against that database. It must stay green: the
new RPCs (`bump_rate_limit`, `refund_rate_limit`, `reserve_mark_usage`,
`release_mark_usage`, `apply_credit_refund`, `patch_whole_paper_question`,
`set_whole_paper_aggregate`) are service-role only; `vote_post` /
`vote_comment` are in the client allowlist on purpose.

## 2. Environment variables (see `.env.example`)

| Var | Action |
|-----|--------|
| `MARK_SHARE_SECRET` | **Set before deploying.** Required in production; `lib/marking/share-token.ts` throws at first use without it. Existing /r and /p links signed with the old `CRON_SECRET` / service-role fallback stop verifying (intended). |
| `UNSUBSCRIBE_SECRET` | Set, or rely on `CRON_SECRET` (accepted in production). With neither, signing throws instead of using a hard-coded string. |
| `ENFORCEMENT_MODE` | Set explicitly. Unset/invalid now means `enforce` in production (logged once) and `off` in dev/test. In `enforce` the gate fails **closed** (503 `billing_unavailable`, nothing charged) when the RPC is unavailable. |
| `ADMIN_EMAILS` | Set explicitly; the founder fallback logs a warning in production. |
| `ONBOARDING_SAVE_SECRET` | Delete — no longer read. |

## 3. Live checks that could not be done from the repo

- **`user_profiles` SELECT policy** (review §3). The base policies predate the
  migrations directory. Run:
  `select policyname, cmd, roles, qual from pg_policies where schemaname='public' and tablename='user_profiles';`
  and
  `select grantee, privilege_type from information_schema.role_table_grants where table_name='user_profiles';`.
  If any SELECT policy has `qual = true` (or there is no SELECT policy while
  `authenticated` holds `SELECT`), add a migration:
  `create policy "user_profiles_select_self_or_teacher" on public.user_profiles for select to authenticated using (id = (select auth.uid()) or id in (select public.teacher_student_ids((select auth.uid()))));`
  after confirming `teacher_student_ids(uuid)` exists and that the teacher
  dashboard's student reads (`app/teacher/**`) go through it. Drop the
  permissive policy it replaces.
- Run `vote_post` / `vote_comment` and the storage policy against a preview
  database before production (plpgsql; not syntax-checked here).
- Confirm `maxDuration = 800` is honoured for `whole-paper/init` and
  `whole-paper/retry` on Fluid Compute (both are now listed in `vercel.json`).

## 4. Client contract changes

- `GET /api/classrooms/by-code/[code]` requires a session (401 otherwise).
  The web join page handles it; the mobile app must send a bearer token.
- `community-uploads`: a signed-in user can only read/list their own folder.
  Mobile must use the server-signed attachment URLs the web API returns.
- `/api/mark/process` may answer `200 { duplicate: true, mark_run_id, status }`
  and `503 { error: 'billing_unavailable', retry: true }`; the web page
  handles both. Successful marks now carry `_allowance.marks_charged` and
  `_allowance.marks_refused`.
- `GET /auth/signout` no longer signs out (303 to `/auth/signout/confirm`);
  only `POST /auth/signout` does.
